# furima-profit-kit

フリマ・物販販売者向けの「実利益・在庫管理キット」を生成する Python プロジェクトです。販売手数料・送料・仕入・梱包費を引いた利益と、未販売商品の滞留日数を確認できます。

## 生成

Python 3.10 以上で実行します。

```sh
python -m pip install -r requirements.txt
python generate.py
```

生成先は `output/実利益・在庫管理キット.xlsx` です。初期状態には受け入れ検証用の販売済み商品 A・B と、在庫商品 C が入っています。利用開始時はサンプルの入力セルを削除・置換してください。

```sh
python generate.py --rows 3000 --year 2027 --output output/2027年管理キット.xlsx
```

`--rows` は販売記録・在庫一覧に用意する行数、`--year` は月次集計の対象年です。初期値は 1,000 行・2026 年です。**生成は既存ファイルを置き換えます。入力済みファイルへの再生成は避け、必ず別名に保存してください。**

## シートと使い方

| シート | 用途 |
| --- | --- |
| はじめに | 入力方法と計算の前提 |
| 販売記録 | 1 商品につき 1 行で入力。手数料・利益を自動計算 |
| 手数料マスタ | プラットフォーム名と手数料率を編集 |
| 在庫一覧 | 状態が「在庫」の商品を自動抽出し、仕入日からの経過日数を表示 |
| 採算シミュレータ | 売値・仕入・送料・梱包費・手数料率から手残りと利益率を計算 |
| 月次集計 | 販売済み商品を販売日で月別集計 |

1. 手数料マスタの率を、実際に利用するサービス・プランに合わせます。初期値は例であり、各サービスの最新の公式条件を確認してください。
2. 販売記録の入力セルを編集します。仕入日は K 列、販売日は A 列です。未販売時は状態を「在庫」とし、売れたら販売日・売値・各費用を入力して「販売済み」にします。費用がない場合も `0` を入力してください。
3. 在庫一覧・月次集計で状況を確認します。在庫一覧の経過日数はブックの再計算時点の日付に基づき、30 日以上を色付けします。月次集計の対象年は B2 セルで変更できます。
4. シミュレータの入力値を変更すると、出品前の採算を確認できます。

青いセルは入力欄、薄緑のセルは数式です。計算セルの数式を消さないでください。用意した空き行を使い切る前に、入力済みファイルのバックアップを保存してください。行数を増やす場合は次の補助スクリプトを使います。入力済みデータを残し、数式・集計範囲・入力規則・条件付き書式をまとめて拡張して別名保存します。Excel で手動で行や列の構成を変えず、元のテンプレート構成で使ってください。

```sh
python extend.py output/実利益・在庫管理キット.xlsx --rows 3000 --output output/実利益・在庫管理キット_3000行.xlsx
```

拡張直後の数式結果は Excel / Google スプレッドシートで再計算されます。必要なら後述の `recalculate.py` でキャッシュを更新できます。

## 計算の前提

- 手数料 = 売値 × マスタの手数料率（1 円未満四捨五入）。実際の明細と丸め方が異なるサービスでは差が出るため、率・計算方法を確認してください。
- 利益／シミュレータの手残り = 売値 − 仕入 − 手数料 − 送料 − 梱包費。
- 利益率 = 利益 ÷ 売値。売値が 0 の場合は率を表示しません。
- 月次集計の仕入は、その月に販売済みになった商品の仕入原価です。仕入支払月の支出を集計するキャッシュフロー表ではありません。
- マスタの率を変更すると、既存の販売記録も新しい率で再計算されます。料金改定前の履歴を保持する場合は、変更前のブックを別名で保管するか、「メルカリ旧料率」のように別名を追加してください。プラットフォーム名は一意にしてください。重複名、空欄・不正な料率は「要確認」になります。
- マスタにないプラットフォームは「要確認」として扱います。名称と率をマスタに登録してから集計結果を確認してください。
- 税金・振込手数料・返品・共通経費は含みません。必要に応じて別途管理してください。

## Excel・Google スプレッドシート

Excel では生成した `.xlsx` を開きます。Google スプレッドシートでは Google ドライブへアップロードして開くか、ファイルのインポートを使います。計算には両者で使える通常の数式を用い、マクロ・動的配列関数は使っていません。

openpyxl は数式を保存しますが、それ自体では計算しません。生成直後の数式結果は、Excel または Google スプレッドシートで開いた際の再計算で表示されます。自動計算を有効にしてください。Google スプレッドシートの画面操作までの自動検証は含みません。

LibreOffice の `soffice` がある環境では、配布前に次のコマンドで計算結果のキャッシュを保存できます。元の数式・書式を維持したまま、LibreOffice が計算した値を反映します。配布用の完成ブックにはこの処理を実施しています。

```sh
python recalculate.py output/実利益・在庫管理キット.xlsx
```

## テスト

LibreOffice の `soffice` を PATH に用意してください。テストでは生成したブックを別の一時ディレクトリへ再計算・保存し、openpyxl の `data_only=True` で実際の計算結果を検証します。

```sh
python -m unittest discover -s tests -v
```

受け入れ値は商品 A の利益 1,700 円、商品 B の利益 590 円、売上合計 6,500 円、利益合計 2,290 円、シミュレータの手残り 900 円です。数式の存在と、入力値変更後の再計算も検証します。
